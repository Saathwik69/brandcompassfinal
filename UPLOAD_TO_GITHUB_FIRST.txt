BRANDCOMPASS — GITHUB + RENDER UPLOAD NOTES
===========================================

This ZIP is arranged so its contents are the repository root. After extracting,
you should immediately see package.json, server.mjs, src/, scripts/, public/,
tests/, drizzle/, samples/, docs/, .github/ and .openai/.

1) GITHUB UPLOAD
----------------
- Open your existing repository: Saathwik69/brandcompassfinal
- Select the main branch.
- Use Add file > Upload files.
- Open the extracted folder and upload ALL its CONTENTS to the repository root.
  Do not upload the ZIP as a single file.
  Do not create an extra BrandCompass/ or project/ folder around the files.
- Include hidden configuration folders .github/ and .openai/ if your file picker
  lets you select them. They are included in this ZIP.
- Commit the upload to main.
- Verify that these exact paths appear in GitHub:
    package.json
    server.mjs
    src/local-db.mjs
    src/api.mjs
    src/security.mjs
    scripts/build.mjs
    scripts/evaluate.mjs
    scripts/smoke.mjs
    public/index.html
    tests/api.test.mjs

2) RENDER WEB SERVICE SETTINGS
------------------------------
- Runtime: Node
- Branch: main
- Root Directory: leave EMPTY
- Build Command: npm ci --ignore-scripts && npm test
- Start Command: npm start
- Health Check Path: /api/health
- Node version: 24 (also selected by .node-version and .nvmrc)

Environment variables:
  NODE_ENV=production
  HOST=0.0.0.0
  ALLOW_SIGNUP=true
  DATA_ENCRYPTION_KEY=<your private random secret>
  AUDIT_SIGNING_KEY=<a different private random secret>

Do not add a PORT value; Render supplies it. Do not upload .env or secret values
to GitHub. Keep the two secrets stable after deployment: changing encryption
secrets can make existing encrypted records unreadable, and changing the audit
signing key can make older audit signatures fail verification.

3) REDEPLOY
------------
After the corrected files are committed to GitHub, open the existing Render
service and choose Manual Deploy > Deploy latest commit.

4) IMPORTANT FREE-PLAN NOTE
---------------------------
The free Render instance can sleep, and its local SQLite database is temporary.
Records can be lost after sleep, restart or redeployment. Do not use it to promise
permanent judge accounts or saved records. The included app's demo workspace can
be recreated for judging.

5) LOCAL VERIFICATION
---------------------
Use Node.js 24, then run:
  npm ci --ignore-scripts
  npm test
  npm start

Open http://localhost:3000 and choose Explore the live demo.
